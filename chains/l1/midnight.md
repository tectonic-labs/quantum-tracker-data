[Midnight](https://midnight.network/) is a privacy-focused sidechain in the Cardano ecosystem, built on the [Kachina protocol](https://docs.midnight.network/) for programmable privacy via zero-knowledge proofs. User transactions do not use traditional digital signatures — instead, they embed cryptographic proofs generated by Kachina, which currently uses [BLS pairing curves](https://docs.midnight.network/blog/zkp) (recently switched from [Pluto-Eris curves](https://github.com/daira/pluto-eris)). Both are elliptic-curve based and quantum-vulnerable. Consensus uses [Minotaur](https://www.gate.com/crypto-wiki/article/what-is-midnight-night-token-privacy-blockchain-fundamentals-by-iog-20251219) (a hybrid PoW+PoS protocol) with Ed25519 for GRANDPA finality voting.

Because Midnight stores zero-knowledge proofs of private state transitions on-chain, a quantum break would not merely compromise future transactions — it would retroactively deanonymize the entire historical ledger. This makes the quantum threat to Midnight's privacy fundamentally different from chains with transparent transactions. IOG's parent-level [Cardano Nightstream initiative](https://bitcoinethereumnews.com/finance/cardanos-quantum-defense-plan-revealed/) targets lattice-based PQC for the Cardano ecosystem, but no Midnight-specific timeline has been published.

Midnight does not currently propose or implement any post-quantum cryptographic algorithms.

## 1. Transaction Signatures

**Grade: F ❌**

Midnight uses a [hybrid transaction model](https://blog.mexc.com/news/midnight-network-the-architecture-of-rational-privacy/). User transactions do not carry traditional digital signatures. Instead, transactions embed cryptographic proofs generated by the [Kachina protocol](https://docs.midnight.network/), which proves valid state transitions over private data using [zero-knowledge circuits](https://docs.midnight.network/academy/module-3). These circuits rely on BLS pairing curves — elliptic-curve based and quantum-vulnerable. Ed25519 is used only for validator consensus messages, not user transaction authorization.

**Current state.** User authorization relies on Kachina's ZK proof system (BLS curves, pairing-based). No post-quantum proof system is available.

**Planned future work.** None documented for Midnight's Kachina proof system.

## 2. Consensus

**Grade: D ⚠️**

Midnight uses [Minotaur](https://www.gate.com/crypto-wiki/article/what-is-midnight-night-token-privacy-blockchain-fundamentals-by-iog-20251219), a hybrid consensus combining Proof-of-Work and Proof-of-Stake to leverage security from the Cardano mainchain. GRANDPA (GHOST-based Recursive ANcestor Deriving Prefix Agreement) provides asynchronous finality, with validators signing attestations using Ed25519.

Midnight launched with federated validators (early 2026), with gradual decentralization planned. The parent organization IOG announced the [Cardano Nightstream initiative](https://coinpedia.org/news/charles-hoskinson-post-quantum-plan-revealed-backed-by-google-and-microsoft-research/) at Consensus Hong Kong in February 2026, targeting lattice-based PQC for the Cardano ecosystem. A Midnight-specific timeline has not been addressed in public announcements.

**Current state.** Ed25519 for GRANDPA validator voting. Federated validator set at launch.

**Planned future work.** The Cardano Nightstream initiative may eventually inform Midnight's consensus PQC roadmap, but no Midnight-specific plan has been published.

## 3. P2P Networking

**Grade: F ❌**

Midnight uses [libp2p](https://docs.midnight.network/operate/network-architecture/p2p-networking) with the [Noise XX protocol](https://docs.libp2p.io/concepts/introduction/overview/) for peer authentication and Ed25519 for node identity keys. GossipSub handles message propagation and Kademlia DHT handles peer discovery. The Ed25519 ECDH component in the Noise handshake is quantum-vulnerable.

**Current state.** Node identity and handshake authentication use Ed25519. No post-quantum networking alternative is documented.

**Planned future work.** None documented.

## 4. On-Chain Logic

**Grade: F ❌**

Midnight runs a custom [ZK VM](https://docs.midnight.network/) specialized for private state transitions, programmed via the Compact DSL (a TypeScript-based language for privacy contracts). The VM verifies zero-knowledge proofs from the Kachina protocol rather than traditional signatures. Proofs are generated off-chain and verified on-chain using BLS pairing curves.

**Current state.** The ZK VM is designed to verify pairing-based proofs, not signatures. No post-quantum proof system is available.

**Planned future work.** None documented. Transitioning to a post-quantum proof system would require redesigning the Kachina protocol, the Compact DSL, and the ZK circuit infrastructure.

## 5. Other Features

**Grade: F ❌**

### Kachina Protocol: Programmable Privacy via ZK Proofs

The [Kachina protocol](https://docs.midnight.network/) enables off-chain private state transitions with on-chain proof verification. Users define privacy-preserving smart contracts in Compact that compute over encrypted state. The protocol generates a zero-knowledge proof of valid computation, submitted to the public ledger for verification. The ledger stores only the proof and public outputs; private data remains in user-controlled local storage.

The proving system originally used [Pluto-Eris curves](https://github.com/daira/pluto-eris) (pairing-friendly curves designed for recursive proofs) and [recently switched to BLS curves](https://docs.midnight.network/blog/zkp) for improved performance. Both rely on the discrete logarithm problem over elliptic curves.

Because zero-knowledge proofs of private transactions are stored on-chain, a quantum adversary could retroactively recover private input values from historical proofs, deanonymizing the entire ledger. This is fundamentally different from transparent-transaction chains, where a quantum break only affects future transactions or exposed public keys.

**Current state.** Kachina uses BLS pairing curves. All private transaction proofs stored on-chain are quantum-vulnerable to retroactive deanonymization.

**Planned future work.** None documented for Midnight specifically. Hash-based proof systems (e.g., zk-STARKs) are a potential alternative that avoids EC dependence, but no transition plan has been published.
